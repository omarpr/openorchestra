# oo-remote Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a phone or tablet on the home LAN follow and type into openOrchestra agent tabs that the user marked for remote control, through an installable PWA served over HTTPS by the running app.

**Architecture:** A new headless crate, `crates/remote` (package `oo-remote`), holds everything testable without the zed cone:
- the `remote.json` store;
- the local CA and certificates;
- pairing and auth;
- the network filter;
- the tmux control-mode bridge;
- the axum HTTPS server (its own tokio runtime) with the embedded PWA;
- keep-awake.

`harness-app` gets a thin `remote` module: it builds a snapshot of the marked agents from app state, starts and stops the server, and adds the marking menu and the Settings → Remote section. The PWA lives in `web/remote/` (Vite + React + TypeScript + Tailwind + shadcn/ui + xterm.js) and is embedded into the crate at compile time.

**Tech Stack:** Rust (tokio, axum 0.8 with `ws`, axum-server with `tls-rustls`, rustls, rcgen, notify 8, rust-embed, if-addrs, sha2, rand, base64), GPUI (existing app), Node/pnpm, Vite, React 18, TypeScript, Tailwind v4, shadcn/ui, @xterm/xterm + @xterm/addon-fit, vite-plugin-pwa, vitest.

**Spec:** `docs/superpowers/specs/2026-11-16-oo-remote-design.md` (read it first; this plan argues from it).

## Global Constraints

- Only marked tabs are reachable. The phone never sends tmux commands or session names; ids map to sessions **only** through the current marks in `remote.json`.
- No plain `tmux attach` for phones. Use tmux control mode only (`tmux -C attach-session -t <s> -f ignore-size`), with output from `%output` lines of the marked pane and input via `send-keys -H` composed by the server.
- Never write `panes.json`. Remote state lives in `~/.openorchestra/remote.json` (0600, atomic, `flock` on `~/.openorchestra/remote.lock`). Every change is a read-modify-write of the file's *current* contents.
- Certificate material lives in `~/.openorchestra/remote/` (dir 0700, files 0600). CA: ECDSA P-256, CN `openOrchestra Remote CA (<computer name>)`, 10-year validity. Server cert: ≤ 397 days; reissue when the SAN set changes or < 30 days remain.
- Default HTTPS port `7443`; setup plain-HTTP port `7080`, listening only while the "Add a phone" panel is open, and serving only `/setup`, `/ca.crt`, `/ca.mobileconfig`.
- Pairing codes: 8 chars from `23456789ABCDEFGHJKMNPQRSTUVWXYZ`, shown `XXXX-XXXX`. They are valid for 10 minutes and single-use. After 5 failed attempts all pending codes are void.
- Accept connections only from loopback, RFC 1918, link-local (and IPv6 `::1`, `fe80::/10`, `fc00::/7`, IPv4-mapped forms normalized).
- Nothing in the remote path runs on the GPUI main thread except cheap snapshot building and file I/O already done by the store (≤ 1 small file).
- Build `harness-app` from `crates/harness-app` (root `cargo build` skips it). The new crate joins the root workspace so `cargo test -p oo-remote` is fast.
- Visual checks use an isolated scratch `.app` + HOME; never touch the user's running Dev app or its tmux server. Live tmux tests use a private `-L` socket and are `#[ignore]`.
- Platforms: iPhone/iPad (`https://<LocalHostName>.local:7443`) and Android phone/tablet (`https://<LAN IP>:7443`).
- UI: shadcn/ui on Tailwind. Phone layout below 768px, two-pane tablet layout at 768px and above. Touch targets ≥ 44px, safe-area insets respected. Light/dark follow the system.

## Review Focus

1. **The phone sleeps or the app is backgrounded, then resumes.** SSE and WebSocket reconnect with backoff, and the terminal redraws cleanly from a fresh init frame (no half-screen garbage). → Task 7 (`reconnects_and_resets_terminal`), Task 5 (`each_ws_gets_init_frame`).
2. **The agent's tmux session dies while a phone watches.** The socket receives `{"type":"closed","reason":"stopped"}`, the list shows STOPPED, and nothing hangs. → Task 4 (`hub_reports_exit`), Task 5 (`dead_session_listed_as_stopped`).
3. **Large pastes, multi-byte UTF-8 and emoji typed from the phone.** They arrive intact, in order, chunked. → Task 4 (`hex_keys_chunks_utf8`).
4. **The Mac's LAN IP changes while serving.** The cert is reissued and hot-reloaded without a restart, and devices paired on the old IP are reported. → Task 2 (`needs_reissue_on_ip_change`), Task 5 (`cert_reload_on_ip_change`), Task 3 (`devices_on_stale_ip`).
5. **`remote.json` is hand-edited into invalid JSON, or two builds write at once.** No crash, no silent loss of paired devices: the bad file is moved to `remote.json.bad` and a fresh one starts, and concurrent updates both land. → Task 1 (`corrupt_file_is_quarantined`, `concurrent_updates_both_land`).

**Files:**
- Create: `crates/remote/src/server.rs` (startup, TLS, reload), `crates/remote/src/api.rs` (routes), `crates/remote/src/assets.rs` (rust-embed of `../../web/remote/dist`), `crates/remote/src/keepawake.rs`
- Create: `crates/remote/build.rs`. If `web/remote/dist/index.html` is missing, it sets cfg `oo_remote_no_web`. `assets.rs` then serves a 503 HTML page saying "Web client not built — run `make web`".

**Interfaces:**
- Consumes: Tasks 1–4.
- Produces:
  - `#[derive(Clone, Serialize, PartialEq)] pub struct AgentInfo { pub id: String, pub title: String, pub agent_kind: Option<String>, pub project: String, pub worktree: String, pub status: String, pub status_since: Option<String>, pub tool: Option<String>, #[serde(skip)] pub session: String }`. `status` is one of `running|waiting|idle|unknown|stopped`.
  - `#[derive(Clone, Default, PartialEq)] pub struct Snapshot { pub agents: Vec<AgentInfo> }`
  - `pub struct ServerConfig { pub state_dir: PathBuf, pub port: u16, pub setup_port: u16 /*7080*/, pub tmux: Tmux, pub bind_ip: IpAddr /*0.0.0.0; tests use 127.0.0.1*/, pub hosts_override: Option<(Vec<String>, Vec<IpAddr>)> /*tests*/ }`
  - `pub enum StartError { PortInUse(u16), Other(String) }`
  - `pub struct ServerStatus { pub urls: Vec<String>, pub ca_fingerprint: String, pub stale_ip_devices: Vec<String> }`
  - `pub struct RemoteServer`, with:
    - `pub fn start(cfg: ServerConfig, snapshot: tokio::sync::watch::Receiver<Snapshot>) -> Result<RemoteServer, StartError>`. It owns a multi-thread tokio runtime on its own threads.
    - `pub fn status(&self) -> ServerStatus`
    - `pub fn set_setup_open(&self, open: bool)`
    - `pub fn stop(self)`
    - `pub fn port(&self) -> u16`
  - `pub fn snapshot_channel() -> (watch::Sender<Snapshot>, watch::Receiver<Snapshot>)` (re-export of `watch::channel(Snapshot::default())`)
  - `pub struct KeepAwake`, with `pub fn start() -> io::Result<KeepAwake>`. It spawns `caffeinate -i -w <own pid>`, and dropping it kills the child.
- Routes (HTTPS). Every route first rejects peers failing `is_allowed_peer` with 403. Auth is `Authorization: Bearer <token>`:
  - `GET /`, static assets, `manifest.webmanifest`, `sw.js`: public. HTML gets the CSP `default-src 'self'; connect-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; frame-ancestors 'none'`.
  - `POST /api/pair {code, device_name}` → `{token}`. The `origin_host` is the request `Host` without the port. Errors: 401 `{"error":"invalid"}` or 423 `{"error":"locked"}`. Rate limit: 5 per minute per peer IP, else 429.
  - `GET /api/me` → `{name, read_only}`.
  - `GET /api/agents` → `[AgentInfo]`: the snapshot filtered to ids still marked in the *current* file. `status` is forced to `stopped` when the session isn't in `live_sessions` (polled every 2s).
  - `GET /api/events` (SSE): an `event: agents` frame with the full list on connect and on every change, plus a keep-alive comment every 15s.
  - `POST /api/agents/:id/send {text}` → 204. Newlines (`\r\n|\r|\n`) are flattened to single spaces, then the text is typed followed by `\r`. Read-only devices get 403, unknown or unmarked ids get 404, stopped agents get 409.
  - `GET /api/term/:id` (WebSocket):
    - The `Origin` header must equal `https://<h>:<port>` for some `h` in the current cert hosts/ips, else 403.
    - The first text frame must be `{"type":"auth","token"}` within 5s, else close 4401.
    - Then the server sends `{"type":"init","cols","rows","read_only"}` followed by a binary frame with the init bytes, then binary frames of live data.
    - Client frames: `{"type":"input","data":"<utf8>"}` and `{"type":"fit","on":bool,"cols","rows"}`. Both are ignored for read-only devices.
    - Server close reasons sent as `{"type":"closed","reason":"stopped"|"unmarked"|"revoked"|"disabled"}` before closing.
  - Setup port (HTTP, only while `set_setup_open(true)`): `GET /setup` (platform-detecting page with the CA fingerprint, and a link to `https://<LocalHostName>.local:<port>/` for Apple or `https://<first private IP>:<port>/` for Android, plus install steps), `GET /ca.crt` (`application/x-x509-ca-cert`), `GET /ca.mobileconfig` (`application/x-apple-aspen-config`). Everything else is 404.
- Behavior:
  - Watch `remote.json` (Task 1). On change, re-authorize every open WebSocket/SSE (revoke → close `revoked`; id no longer marked → close `unmarked`).
