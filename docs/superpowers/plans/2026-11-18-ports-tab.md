# Ports Tab (Step 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Ports tab in the right-hand tools column listing the selected task's listening TCP ports and the rest of the Mac's, with Open in browser and Copy URL.

**Architecture:** A pure `ports` module parses `lsof` and `ps` output and classifies listeners into "This task" and "Other on this Mac" using the same tmux session-prefix attribution the footprint monitor uses. A background loop samples every 3 s only while the Ports tab is visible; the UI thread does the cheap classification and renders it.

**Tech Stack:** Rust, GPUI, `lsof`, `ps`, `tmux list-panes`.

**Spec:** `docs/superpowers/specs/2026-11-18-ports-panel-design.md` (Step 1 only).

## Global Constraints

- Build and test from `crates/harness-app` (`cargo test` at the root silently skips it). Don't run `cargo fmt`.
- No new crates.
- TCP listeners only. Command: `lsof -nP -iTCP -sTCP:LISTEN -F pcn` (process names from `lsof` are unreliable: Claude Code shows as `2.1.327`; take names from `ps`).
- Sampling only while the Ports tab is visible; one immediate sample when it is selected.
- CHANGELOG.md gets an Unreleased line.

## Review Focus

- Same port on IPv4 and IPv6 (`*:5173` and `[::1]:5173`) from one process → one row, both addresses.
- Process names with spaces (`LM Studio`, `OrbStack Helper`) parse intact from `ps`.
- `lsof` or `tmux` missing/failing → empty lists, never a panic; the tab shows its empty state.
- A dev server started by `npm run dev` (shell → node → child) is attributed to the task through the whole subtree, not just the pane's direct child.
- The agent CLI's own loopback listener (claude) does not appear under "This task".

**Interfaces (Produces):**
```rust
pub struct Listener { pub pid: u32, pub addr: String, pub port: u16 }       // addr: "*", "127.0.0.1", "::1"
pub struct ProcPath { pub pid: u32, pub parent: Option<u32>, pub path: String }
pub struct PortsSample { pub app_pid: u32, pub listeners: Vec<Listener>, pub procs: Vec<ProcPath>, pub session_panes: Vec<(String, u32)> }
pub struct Scope { pub label: String, pub session_prefix: String }
#[derive(Clone, Debug, PartialEq)]
pub struct PortRow { pub port: u16, pub addrs: Vec<String>, pub pid: u32, pub name: String, pub member: Option<String> }
#[derive(Clone, Debug, Default, PartialEq)]
pub struct PortsView { pub task: Vec<PortRow>, pub other: Vec<PortRow> }

pub fn parse_lsof(out: &str) -> Vec<Listener>;
pub fn parse_ps_paths(out: &str) -> Vec<ProcPath>;      // `ps -axo pid=,ppid=,comm=`
pub fn classify(s: &PortsSample, scopes: &[Scope]) -> PortsView;
pub fn sample(has_tmux: bool) -> PortsSample;           // blocking; runs lsof, ps, tmux
pub fn url(port: u16) -> String;                        // "http://localhost:<port>"
```

Rules for `classify`:
- Group listeners by `(pid, port)`; `addrs` sorted and deduplicated. Rows sorted by port, then pid.
- `name` = basename of the process path (`"?"` if unknown).
- Task rows: pid in the subtree of any pane whose session starts with a scope's prefix; `member = Some(scope.label)` when `scopes.len() > 1`, else `None`. Drop rows whose lowercased name is in `preflight::AGENTS`.
- Other rows: everything else, except `pid == app_pid` and paths starting with `/System/` or `/usr/libexec/`.
